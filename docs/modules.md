# Настройка дополнительных модулей

Модули подключаются независимо друг от друга. Проще всего — положить env-файл в рабочий
каталог (Hermes подхватит) и, при необходимости, добавить пару строк в `configs/config.py`.

## Битрикс24

Зачем: выгрузка результатов разведки прямо в карточку компании (поля + таймлайн).

1. В Битрикс24 создайте **входящий вебхук** (Приложения → Вебхуки) с правами:
`crm.company.get/update`, `crm.timeline.comment.add`, `crm.requisite.\\\*` (опционально).
2. Скопируйте URL вида `https://<ваш-домен>/rest/<N>/<ключ>/` в файл `.env.b24` (mode 600):
`BITRIX\\\_WEBHOOK\\\_URL=http://<host>/rest/<N>/<key>`
3. В бизнес-процессе добавьте шаг «Исходящий вебхук»/PHP-активити, который передаёт
агенту `company\\\_id` (ID компании в Б24) вместе с названием/ИНН — тогда `bitrix\\\_sync.py`
сможет записать результат.
4. Проверка: `bitrix\\\_sync.py <company\\\_id> "<папка разведки>" --dry`.

Нюансы:

* поле «Ликвидирована» ставится автоматически, если разведка подтвердила ликвидацию;
* карточка в таймлайн отправляется BBCode-разметкой (\[URL=...], \[B], \[LIST]) и чанками ≤14000;
* множественные PHONE/EMAIL/WEB: телефон нормализуется к `+7XXXXXXXXXX`, email — lowercase;
* идемпотентность: повторный синк не дублирует таймлайн (маркер `.b24\\\_synced` в папке).

### Поля Битрикс24: что использует конвейер

Значения записываются методом `crm.company.update` (ID компании передаётся из БП).
Поля делятся на **стандартные** (есть в любом Б24) и **пользовательские** (нужно создать,
техническое название указано в `bitrix\_sync.py` — замените на свои после создания).

#### Стандартные поля (создавать не нужно)

|Техн. название|Поле|Назначение|
|-|-|-|
|`TITLE`|Название|Нормализованное название: коммерческое имя + сокращённые ОПФ («Энергия НПП АО»), без юр-формы в начале|
|`PHONE`|Телефоны (множ.)|Контакты с сайта/TenChat, нормализация `+7XXXXXXXXXX`, тип WORK|
|`EMAIL`|E-mail (множ.)|Контакты, lowercase, тип WORK|
|`WEB`|Сайты (множ.)|Официальный домен + подтверждённые альтернативные TLD|
|`COMMENTS`|Комментарий|Не используется (дубль карточки запрещён — карточка уходит в таймлайн)|
|`EMPLOYEES`|Кол-во сотрудников|crm\_status `EMPLOYEES\_1..4` из Checko (менее 50 / 50-250 / 250-500 / более 500)|
|`REVENUE`|Годовой оборот|Из отчётности Checko (строка 2110), целое число|

#### Пользовательские поля (создать → заменить техн. название в bitrix\_sync.py)

|Техн. название (наш инстанс)|Поле|Тип в Б24|Назначение|
|-|-|-|-|
|`UF\_CRM\_1641979956293`|Рейтинг|Число (double) 0–10|Скоринг интереса компании под ваш профиль (company-capabilities.md)|
|`UF\_CRM\_1642689459464`|Дата актуализации|Дата|Когда разведка выполнялась (авто: сегодня)|
|`UF\_CRM\_1620195662116`|Ликвидирована|Да/Нет (bool)|`Y` при подтверждённой ликвидации (≥2 независимых источника)|
|`UF\_CRM\_1729834961463`|Собственное оборудование|Список (одиночный)|Оборудование компании: Лазер / Плазма / Гибка / Вальцовка / Гидроабразив / Сварка / Штамповка / Токарка / Фрезеровка / Порошковая покраска (ID 1850–1859)|
|`UF\_CRM\_1725001632`|Направление|Список (множ.)|Производство оборудования / Строительство / Конечный потребитель / Ремонт-восстановление / Производство инструмента / Обслуживание (ID 1807–1810, 1981, 2111)|
|`UF\_CRM\_1725001635`|Сфера|Список (множ.)|Отрасль компании: 30+ значений (Машиностроение, Металлообработка, Нефтегаз, Авиация, … Другое)|
|`UF\_CRM\_1788855304769`|Есть данные разведки|Да/Нет (bool)|Финальная галка: разведка завершена и выгружена (ставится последним шагом)|

Порядок создания: Настройки → CRM → Настройки форм и отчётов → Пользовательские поля →
Создать (тип «Список» — заполнить значения, их ID выдаст Б24). Затем в `bitrix\_sync.py`
замените `UF\_CRM\_\*` на технические названия своих полей (7 вхождений).

Значения списков (ID) в скрипте — с нашего инстанса Б24; у вас они будут другими.
Логику маппинга (`UF\_DIRECTION`, `UF\_SPHERE`, `UF\_OWN\_EQUIPMENT`) менять не нужно —
только ID-значения под ваши списки.

Таймлайн не использует пользовательских полей: карточка пишется `crm.timeline.comment.add`
в BBCode, чанками ≤14000 символов.

## Яндекс / Google (альтернативные поисковики)

Зачем: резерв, когда DDGS выдача слабая; Google — свежие новости, Yandex — российские сайты.

* **Google (SerpAPI)**: получите ключ на serpapi.com → env `SERPAPI\\\_KEY`.
Запуск: `search\\\_all.py "запрос" google 3`. Ограничение: 1 запрос / 10 мин.
* **Yandex XML**: ключи из yandex.com/search/xml → env `YANDEX\\\_USER`, `YANDEX\\\_KEY`.
* Без ключей движки просто не активируются, конвейер работает на DDGS.

## Checko API

Зачем: карточка/финансы/госзакупки/арбитраж в одном запросе, без 429 и капчи.

1. Оформите тариф на api.checko.ru (рекомендуется ≥100 запросов/день, все методы).
2. Ключ → `.env.checko`: `CHECKO\\\_API\\\_KEY=...`
3. requisites\_parser сам переключается на API (HTML — резерв при исчерпании лимита).
Следите за `meta.today\\\_request\\\_count` в ответах.

## VK API

Зачем: сообщество ВКонтакте, посты, поиск сотрудников.

1. Создайте приложение на dev.vk.com → сервисный ключ (`VK\\\_SERVICE\\\_TOKEN`)
— для групп.getById/wall.get/database.getCities.
2. Для поиска сотрудников нужен **пользовательский** токен (`VK\\\_USER\\\_TOKEN`) —
парсер выбирает его автоматически, если найдёт в env-файле.

## Headless Chromium (браузерные методы)

Зачем: ЕИС (zakupki.gov.ru), b2b-center, corpmsp — SPA, которые не отдают статику.

```bash
chromium --headless --no-sandbox --disable-gpu --ignore-certificate-errors          --remote-debugging-port=9222 --remote-allow-origins=\\\* about:blank \\\&
pip install websocket-client
```

Запуск: `cdp\\\_parse.py eis|eis\\\_done|eis\\\_contract|b2b\\\_market|b2b\\\_archive <ИНН|название>`.
Из IP датацентра b2b-center может отдавать 403 — тогда только b2b-площадки заказчика.

## Прокси (опционально)

`fetch\\\_url.py` уважает стандартные `http\\\_proxy`/`https\\\_proxy` из окружения.
Для SOCKS5 (напр. sing-box на 127.0.0.1:7891) укажите env:
`http\\\_proxy=socks5://127.0.0.1:7891 https\\\_proxy=socks://127.0.0.1:7891`.
DDGS и Checko API работают без прокси.

## Ежедневная очистка (cron)

```
0 7 \\\* \\\* \\\* python3 {BASE\\\_DIR}/scripts/cleanup\\\_old\\\_intel.py
```

Пишет в `{BASE\\\_DIR}/cleanup.log` только когда реально что-то удалил.
