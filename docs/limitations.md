# Известные ограничения и обходные пути

## Среда (IP датацентра)

- **vk.com**: login-wall (пустой SPA-скелет) — только API или поисковые сниппеты;
- **tgstat.ru**: Cloudflare 403 гостю — данные через telegram-dialogs.ru (открыт) и сниппеты;
- **t.me**: TCP к Telegram заблокирован на многих хостингах — посты берутся из dialogs-источника;
- **b2b-center**: 403 из датацентра — только если у компании есть ЭТП на b2b и вы со своим IP;
- **ЕИС zakupki.gov.ru**: самоподписанный сертификат (`verify=False` только для этого домена);
  SPA-страницы — только через headless Chromium;
- **Checko**: 429 при батчах (окно ~90-300с) и капча — решается паузами/ручным решением капчи с устройства с тем же IP;
  API-тариф снимает обе проблемы.

## API-лимиты

| Источник | Лимит | Действие при исчерпании |
|----------|-------|------------------------|
| Checko API | 100/день (meta.today_request_count) | авто-фолбэк на HTML-парсер |
| Google (SerpAPI) | 1 запрос/10 мин | DDGS (авто) |
| hh.ru | пауза ≥5 с между страницами | ретрай 10/20 с на 429/5xx |

## Что сознательно НЕ собирается

- **Парсинг сотрудников ВК** (users.search недоступен сервисному токену; вручную — по шаблонам
  в карточке). Требуется пользовательский токен. Так как сотрудников может быть найдено действительно много, а должности либо не видны, либо не указываются, логичнее оставить как есть и вручную по ссылке посмотреть найденные результаты.
- **Контактные лица из вакансий** — только если прямо указаны в вакансии.
- **Полный обход каталога сайта** — только целевые разделы (меню главной = карта URL).

## Известные тонкости парсинга

- **Wayback-копии**: старые сайты часто в cp1251 — декодировать байты; wayback-шапка
  (toolbar, «N captures») вырезается маркерами.
- **pypdf и вёрстка**: межбуквенные пробелы в фамилиях («Г арькин») — при поиске в PDF
  искать хвост фамилии или нормализовать пробелы.
- **Пагинация-ловушка**: если `?page=2` отдаёт страницу 1 (JS-навигация) — пагинации нет,
  стоп (сравнить первый пост страниц).
- **Тёзки-однофамильцы**: сверять ИНН каждой новости/контакта перед записью.
- **MX-домен группы**: чужой MX = связанная компания группы (учитывать в скоринге).
- **Титульная нормализация**: «Научно-производственное предприятие Энергия АО» →
  «Энергия НПП АО» (полные ОПФ сокращаются, коммерческое название — первым).

## Осознанно процесс выстроен последовательно

Если хотите ускорить, можно попробовать запараллелить. Но для моих задач и с моими требованиями (5-10 минут на 1 компанию) - это не проблема и позволяет более коррктно собирать данные и делать из них выводы
